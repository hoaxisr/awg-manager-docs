В awg-manager несколько механизмов выборочной маршрутизации, и они решают разные задачи. Эта страница помогает выбрать подходящий — по сравнительной таблице и типовым сценариям. Если не знаете, что выбрать, берите [AWGM Route](../awgm-route/).

## Сравнение механизмов

| Механизм | Матчит по | OS | Уровень | Особенности |
|---|---|---|---|---|
| [**AWGM Route**](../awgm-route/) | доменам, подсетям | — | Базовый | **Рекомендуется.** Решение по имени сайта, готовые списки, резервные интерфейсы, мониторинг |
| [DNS (NDMS)](../dns-routing/) | доменам | 5.x | Базовый | Штатный механизм прошивки; в 2.22.0 будет убран из интерфейса |
| [По IP](../ip-routing/) | IP / CIDR | 4.x, 5.x | Расширенный | Не зависит от DNS клиента; Kill Switch; импорт `.bat` |
| [VPN для устройств](../clientvpn/) | устройству | 4.x, 5.x | Базовый | Весь трафик устройства — в один туннель |
| [Политики доступа](../policy/) | группе устройств | 5.x | Расширенный | Приоритет интерфейсов с fallback |
| [Sing-box: TProxy](../singbox/router/) | доменам, rule-set'ам, IP, портам | 5.x | Продвинутый | Точность по доменам за CDN; блокировка; composite-выходы |
| [Sing-box: Fake-IP](../singbox/router/#режим-fake-ip) | доменам, rule-set'ам | 5.x | Продвинутый | То же без правки DNS у клиентов; быстрее TProxy для direct соединений|
| [Autolist](autolist/) | доменам и STUN/TURN IP | 5.x | Продвинутый | Находит блокировки по живому трафику и добавляет цели в Sing-box |

## Типовые сценарии

**Просто хочу нажать две кнопки** → [AWGM Route](../awgm-route/quickstart/): установить компонент, создать туннель и добавить группы из каталога сервисов.

**Не знаю заранее, какие сайты заблокированы** → [Autolist](autolist/). Он замечает недоступные цели по реальному трафику и предлагает или сам добавляет правило в Sing-box Router.

**Сервис известен по IP-диапазонам (Telegram, Discord), или у клиентов свой DNS/DoH** → [Маршрутизация по IP](../ip-routing/). DNS-правила такому клиенту не помогут — запросы идут мимо роутера, а IP-маршруты работают всегда.

**Роутер на Keenetic OS 4.x** → [Маршрутизация по IP](../ip-routing/): вкладка NDMS доступна только на 5.x.

**Правила NDMS «то работают, то нет»** → [перейдите на AWGM Route](../awgm-route/#переход-с-маршрутизации-ndms).

**Одно устройство должно целиком ходить через VPN (рабочий ноутбук), другое — целиком мимо (Smart-TV)** → [VPN для устройств](../clientvpn/). Правило «устройство → туннель» с Kill Switch или bypass при падении.

**Хочу все максимально контролировать, порты, протоколы, клиенты** → [Sing-box Router](../singbox/router/). Сопоставление по перехваченному DNS-запросу даёт точность по доменам; есть готовые rule-set'ы (sing-geosite/sing-geoip) и действие «Заблокировать».

**Как Sing-box TProxy/OpkgTun, но я понимаю как работает singboх** → режим [Fake-IP](../singbox/router/#режим-fake-ip): достаточно указать один DNS-адрес в настройках роутера, устройства не трогаем. Цена - могут быть сюпризы с UDP трафиком, его нечем направить в движок. (для предсобранных правил эта проблема решается, для кастомных правил нет)

## Как механизмы взаимодействуют

- **AWGM Route и Sing-box Router — два разных движка**: активен только один. Переключение — через [мастер миграции](../awgm-route/quickstart/#если-вы-уже-пользуетесь-sing-box).
- **Не держите одни и те же домены** одновременно в AWGM Route и в NDMS.
- **VPN для устройств срабатывает раньше всех (кроме Singbox)**: `ip rule` по source IP перекрывает DNS- и IP-правила для этого устройства.
- **Sing-box Router ультимативно управляет маршрутизацией** — устройства выбранной политики (или весь роутер, если так настроено) при этом никакие иные системы маршрутизации работать не будут, в т.ч. и VPN для устройств.
- **Один и тот же туннель** может быть целью в любом механизме одновременно — это просто интерфейс роутера.
- Правила, оставшиеся без туннеля после его удаления, становятся «orphan» и не применяются до переназначения.
