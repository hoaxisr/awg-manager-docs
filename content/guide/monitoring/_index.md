{{< pagemeta level="Базовый" ui="Инструменты → Мониторинг" >}}
Мониторинг — это автоматическая проверка связности через туннель: awg-manager периодически отправляет пробы через интерфейс и поддерживает картину того, какие туннели сейчас реально доносят трафик до интернета, а какие — нет. На основе этих проб работает автоперезапуск упавших туннелей и принимаются решения в зависимых разделах (Маршрутизация, Sing-box Router).

{{< callout type="info" >}}
В версии 2.15.0 мониторинг переработан: отдельный пункт меню «Мониторинг» и cross-target матрица «цель × туннель» убраны. Теперь мониторинг — это вкладка **[Инструменты](../diagnostics/) → Мониторинг** с гридом карточек-watchdog, доступная на любом уровне использования. Каждый туннель проверяет собственную цель — сводной матрицы по нескольким целям больше нет.
{{< /callout >}}

## Открыть раздел

Главное меню → **Инструменты** → вкладка **Мониторинг** (вторая, сразу после Журнала).

## Карточки-watchdog

![Вкладка Мониторинг: грид карточек-watchdog](/img/guide/monitoring/cards.png)

Каждому туннелю соответствует карточка:

- **Шапка** — индикатор состояния и имя туннеля, бейджи backend'а (kernel / nativewg) и версии AWG, статус мониторинга: `активен` (зелёный), `восстановление` (жёлтый — мониторинг перезапускает туннель), `ждём первого интервала` (первая проверка ещё не прошла), `выключен`, `остановлен`.
- **Строка конфигурации** — что именно проверяется: метод, цель, интервал и порог сбоев (например, `ICMP → 8.8.8.8 · 10с · порог 3`).
- **Метрики** — четыре ячейки: средний RTT (**avg**), счётчик **сбоев**, счётчик **рестартов** и **loss** (% потерь, подсвечивается красным при потерях).
- **Последние проверки** — spark-бары последних замеров (цвет каждого бара по величине задержки) с min/max и журнал последних проверок: время, успех/ошибка, задержка. Клик по барам запускает проверку немедленно.
- **Кнопки** — **Выключить** / **Включить** мониторинг прямо на карточке и **Настроить** (открывает панель настроек pingcheck). Если мониторинг выключен, настройки сохраняются — включить обратно можно одной кнопкой.

Для sing-box-туннелей и подписок своя система проверки задержки (Clash urltest) — она описана в [Sing-box Router](../singbox/router/).

## Kernel vs NativeWG

Под капотом мониторинг состоит из двух разных механизмов, и какой работает — определяется типом туннеля. Для **Kernel**-туннелей awg-manager сам гоняет цикл проверок (ICMP или HTTP — по настройке) и сам принимает решение о рестарте; никаких системных компонентов Keenetic для этого не требуется. Для **NativeWG**-туннелей awg-manager делегирует проверку встроенному компоненту Keenetic OS **ping-check** (NDMS): создаёт профиль с нужными параметрами, читает его статус и логирует переходы. Если компонент `ping-check` в прошивке не установлен, мониторинг NativeWG-туннелей просто недоступен — устанавливается через веб-интерфейс роутера (**Управление → Общие настройки → Изменить набор компонентов → ping-check**).

Кнопка **Настроить** на карточке открывает панель, соответствующую типу туннеля:

- **Kernel** — метод (ICMP / HTTP), цель, интервал проверки, dead-интервал и порог сбоев.
- **NativeWG** — быстрые пресеты (ICMP 8.8.8.8 / ICMP 1.1.1.1 / TCP 8.8.8.8:53 / TLS 1.1.1.1:443), поля хост / метод (ICMP / TCP Connect / TLS) / порт, интервал, максимум сбоев, минимум успехов, таймаут и тумблер **Перезапуск при dead** (автоматически перезапускать туннель при потере связи). Пределы значений задаёт сам компонент ping-check NDMS.

![Панель настройки pingcheck](/img/guide/monitoring/pingcheck-modal.png)

С 2.15.0 для NativeWG-туннелей до первой проверки показывается статус «ждём первого интервала» вместо ложного FAIL.
